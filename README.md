# lore

Working knowledge for builders and agents. Not tutorials. Not glossaries. The patterns that hold up, the traps that bite you, the techniques worth internalizing.

Each file covers one topic at the meta level — what to do, what to avoid, what gets overlooked.

---

## Structure

```
lore/
├── dev/          Software development
├── business/     Business, finance, marketing, ops
├── product/      Product management and strategy
├── design/       UX, UI, branding, accessibility
├── legal/        Contracts, IP, privacy, compliance
└── facilities/   Plant/facility engineering — ventilation, electrical, mechanical
```

## Contributing

See [CONTRIBUTING.md](CONTRIBUTING.md).

New entries should follow the same format: working knowledge, not documentation. If it reads like a Wikipedia article, it's not the right fit. If it reads like advice from someone who's been burned before, it is.
